Django'ya giriş: MVT, ORM, admin ve DRF

Django projesi ve uygulaması kurar; URL, view, model, migration, admin, şablon, form ve kimlik doğrulamayı tanır; ORM sorgularını (filter, exclude, annotate, aggregate, select_related) SQL karşılıklarıyla birlikte düşünmeyi Anadolu Market örneğiyle öğrenirsin.

Uygulamada aç, 30 alıştırmayı çözÜcretsiz, hesap gerekmez, kurulum yok.

Neden Django?

Flask ve FastAPI derslerinde küçük, esnek çatıları (framework) gördün: yönlendirme verirler, gerisini sen seçersin. Django ise "pili içinde" (batteries included) yaklaşımıyla gelir: ORM, migration sistemi, admin paneli, kullanıcı ve yetki sistemi, form doğrulama, şablon motoru, önbellek (cache), e-posta ve güvenlik korumaları tek pakette ve birbiriyle uyumlu. Anadolu Market'in iç yönetim paneli, Ilgaz Bank'ın kredi başvuru takip ekranı ya da belediyenin randevu sistemi gibi veritabanı ağırlıklı, formlu, yetkili kullanıcılı uygulamalarda Django ile birkaç günde çalışan bir ürün çıkarabilirsin.

Django tarayıcıda çalışmazBu dersteki Django kodları pre kutularında gösterim içindir; kendi bilgisayarında denemen gerekir. Çalıştırılabilir kutular ve alıştırmalar ise Django'nun arkasındaki mantığı (QuerySet, URL eşleme, form doğrulama, migration SQL'i) saf Python ve sqlite3 ile taklit eder. Böylece Django'yu "sihir" olarak değil, anlaşılır bir makine olarak öğrenirsin.

MVT: Model, View, Template

Django kendi mimarisine MVT der. Klasik MVC ile eşleşmesi biraz kafa karıştırır: Django'nun "view"u MVC'deki controller'a, "template"i MVC'deki view'a karşılık gelir.

KatmanGöreviDosya
ModelVeri yapısı ve iş kuralları; tabloya eşlenirmodels.py
Viewİsteği alır, modelden veri çeker, yanıt döndürürviews.py
TemplateHTML üretimi; mantıktan arındırılmış sunumtemplates/
URLconfYolu doğru view'a yönlendirirurls.py

Bir isteğin yolculuğu: tarayıcı /urunler/42/ ister → ara katmanlar (middleware: oturum, CSRF, güvenlik başlıkları) çalışır → URLconf deseni eşler ve pk=42 yakalar → view modeli sorgular → şablon HTML üretir → yanıt yine ara katmanlardan geçip döner.

Desenler yukarıdan aşağıya denenir ve ilk eşleşen kazanır. <int:pk> bir dönüştürücüdür (converter): yalnız rakamları eşler ve değeri int olarak view'a verir. Diğerleri: str (eğik çizgi hariç her şey), slug, uuid, path. Arka planda her desen bir düzenli ifadeye çevrilir; aşağıdaki kutu bu fikri taklit ediyor.

import re

DONUSTURUCU = {"int": (r"[0-9]+", int), "str": (r"[^/]+", str), "slug": (r"[-a-zA-Z0-9_]+", str)}

def derle(desen):
    cevirici = {}
    def degistir(m):
        tur, ad = m.group(1), m.group(2)
        cevirici[ad] = DONUSTURUCU[tur][1]
        return f"(?P<{ad}>{DONUSTURUCU[tur][0]})"
    regex = re.sub(r"<(\w+):(\w+)>", degistir, desen)
    return re.compile("^" + regex + "$"), cevirici

regex, cevirici = derle("urunler/<int:pk>/")
for yol in ["urunler/42/", "urunler/abc/", "urunler/7"]:
    m = regex.match(yol)
    if m:
        print(yol, "->", {k: cevirici[k](v) for k, v in m.groupdict().items()})
    else:
        print(yol, "-> 404")

Modeller ve ORM

Model, bir tabloyu temsil eden Python sınıfıdır. Her alan (field) bir sütundur; id birincil anahtarı otomatik eklenir.

# magaza/models.py
from django.db import models

class Kategori(models.Model):
    ad = models.CharField(max_length=60, unique=True)

class Urun(models.Model):
    ad = models.CharField(max_length=120)
    kategori = models.ForeignKey(Kategori, on_delete=models.PROTECT, related_name="urunler")
    fiyat = models.DecimalField(max_digits=10, decimal_places=2)
    stok = models.PositiveIntegerField(default=0)
    aktif = models.BooleanField(default=True)
    eklenme = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.ad

Urun.objects bir yöneticidir (manager); ondan dönen QuerySet iki özelliğe sahiptir: tembeldir (lazy), yani üzerinde döngü kurana, len, list ya da dilim uygulayana kadar veritabanına gitmez; ve zincirlenebilirdir, her filter yeni bir QuerySet döndürür, eskisini değiştirmez. Alan adı ile işlem arasına çift alt çizgi koyarak sorgu yaparsın; buna lookup denir.

Aşağıdaki kutu, zincirlenebilir ve lookup destekli bir QuerySet'in özünü 20 satırda taklit ediyor. Alıştırmalarda bunu adım adım sen kuracaksın.

ISLEM = {
    "exact": lambda a, b: a == b,
    "gt": lambda a, b: a > b,
    "lte": lambda a, b: a <= b,
    "icontains": lambda a, b: b.lower() in a.lower(),
}

class Sorgu:
    def __init__(self, kayitlar, kosullar=()):
        self.kayitlar, self.kosullar = kayitlar, list(kosullar)
    def filter(self, **kw):
        return Sorgu(self.kayitlar, self.kosullar + list(kw.items()))
    def __iter__(self):                      # tembel: ancak gezilince çalışır
        for k in self.kayitlar:
            if all(ISLEM[(a.split("__") + ["exact"])[1]](k[a.split("__")[0]], v)
                   for a, v in self.kosullar):
                yield k

urunler = [{"ad": "Rize Çayı", "fiyat": 120}, {"ad": "Türk Kahvesi", "fiyat": 350},
           {"ad": "Yeşil Çay", "fiyat": 90}]
qs = Sorgu(urunler).filter(ad__icontains="çay")
ucuz = qs.filter(fiyat__lte=100)

Django'nun yaptığını küçük ölçekte taklit edelim: dataclass alanlarından CREATE TABLE üretmek.

from dataclasses import dataclass, fields

TIP = {int: "INTEGER", str: "VARCHAR(120)", float: "REAL", bool: "BOOL"}

@dataclass
class Musteri:
    ad: str
    sehir: str
    puan: float
    aktif: bool

def create_table(model):
    sutunlar = ['"id" INTEGER PRIMARY KEY AUTOINCREMENT']
    sutunlar += [f'"{f.name}" {TIP[f.type]} NOT NULL' for f in fields(model)]
    return f'CREATE TABLE "magaza_{model.__name__.lower()}" (' + ", ".join(sutunlar) + ");"

from django import forms

class UrunFormu(forms.ModelForm):
    class Meta:
        model = Urun
        fields = ["ad", "kategori", "fiyat", "stok"]

    def clean_fiyat(self):
        fiyat = self.cleaned_data["fiyat"]
        if fiyat <= 0:
            raise forms.ValidationError("Fiyat pozitif olmalı.")
        return fiyat

@login_required

Aynı doğrulama akışının saf Python taklidi:

class UrunFormu:
    def __init__(self, veri):
        self.veri, self.errors, self.cleaned_data = veri, {}, {}
    def is_valid(self):
        ad = self.veri.get("ad", "").strip()
        if not ad:
            self.errors["ad"] = "Bu alan zorunlu."
        try:
            fiyat = float(self.veri.get("fiyat", ""))
            if fiyat <= 0:
                self.errors["fiyat"] = "Fiyat pozitif olmalı."
        except ValueError:
            self.errors["fiyat"] = "Geçerli bir sayı gir."
        if not self.errors:
            self.cleaned_data = {"ad": ad, "fiyat": fiyat}
        return not self.errors

f = UrunFormu({"ad": "  Rize Çayı ", "fiyat": "120.5"})
print(f.is_valid(), f.cleaned_data)
g = UrunFormu({"ad": "", "fiyat": "bedava"})
print(g.is_valid(), g.errors)

Django REST Framework (DRF)

Mobil uygulama ya da React ön yüz için JSON API gerekiyorsa DRF eklenir (pip install djangorestframework). Serializer, ModelForm'un API karşılığıdır.

from rest_framework import serializers, viewsets, routers, permissions

class UrunSerializer(serializers.ModelSerializer):
    class Meta:
        model = Urun
        fields = ["id", "ad", "fiyat", "stok"]

class UrunViewSet(viewsets.ModelViewSet):
    queryset = Urun.objects.select_related("kategori").filter(aktif=True)
    serializer_class = UrunSerializer
    permission_classes = [permissions.IsAuthenticatedOrReadOnly]

router = routers.DefaultRouter()
router.register("urunler", UrunViewSet)   # GET/POST /urunler/, GET/PUT/DELETE /urunler/5/

Parça şablonu ve HX-Request

Django'da parça şablonu ayrı bir dosyadır ve tam sayfa şablonunda {% include %} ile kullanılır. Görünüm, request.headers ile HTMX isteğini tanır; django-htmx paketi bunu request.htmx olarak kısaltır. Sayfalamada Django'nun Paginator sınıfı kullanılır.

# urunler/views.py
from django.core.paginator import Paginator
from django.shortcuts import render
from .models import Urun

def urun_listesi(request):
    q = request.GET.get("q", "")
    qs = Urun.objects.filter(ad__icontains=q).order_by("id")
    sayfa = Paginator(qs, 12).get_page(request.GET.get("sayfa"))

        return render(request, "urunler/_satirlar.html", baglam)
    return render(request, "urunler/liste.html", baglam)

    if isinstance(o, Decimal):
        return str(o)
    raise TypeError(f"{type(o).__name__} JSON'a çevrilemez")

print(json.dumps(kitaplar, default=ondalik, ensure_ascii=False))

JsonResponse ve fetch

JSON uç noktası için DRF şart değildir; küçük işlerde JsonResponse yeter. İki ayrıntı: varsayılan safe=True yalnız sözlük kabul eder (liste için safe=False), ve DecimalField değerleri Django'nun kodlayıcısında metne çevrilir. Türkçe karakterlerin kaçırılmaması için json_dumps_params={"ensure_ascii": False} verilebilir.

import json
from django.http import JsonResponse
from django.views.decorators.http import require_POST

@require_POST
def sepet_api(request):
    try:
        govde = json.loads(request.body)
    except json.JSONDecodeError:
        return JsonResponse({"hata": "geçersiz JSON"}, status=400)
    form = SepetFormu(govde)                       # Django formu JSON ile de çalışır
    if not form.is_valid():
        return JsonResponse({"hatalar": form.errors}, status=422)
    return JsonResponse({"tutar": str(form.tutar())})

def kategoriler(request):
    return JsonResponse(list(Kategori.objects.values("id", "ad")), safe=False,
                        json_dumps_params={"ensure_ascii": False})

Form hataları HTMX ile

HTMX 2, varsayılan olarak 4xx/5xx yanıtları sayfaya yerleştirmez. Form hatalarını göstermek için iki yol var: hatalı formu 200 ile parça olarak döndürmek, ya da 422 dönüp HX-Retarget ve HX-Reswap yanıt başlıklarıyla hataların nereye konacağını söylemek (ve istemcide 422'yi yerleştirmeye izin veren yapılandırmayı açmak). Hangi yolu seçersen seç, kural aynıdır: doğrulama her zaman sunucuda yapılır.

Gerçek işteDjango + HTMX, özellikle iç sistemlerde (bayi portalı, İK izin ekranı, stok paneli) yaygınlaşıyor: admin paneli, kimlik doğrulama ve form doğrulaması hazır gelir; ön yüz projesi gerekmez. Mobil uygulama ya da dış ortaklar için ise aynı modeller üzerine DRF API eklenir. Mülakatta "Django ile SPA" sorulursa CSRF'nin başlıkla gönderildiğini ve CORS'un ayrı bir konu olduğunu söyleyebilmelisin.
