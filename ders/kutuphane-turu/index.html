Python kütüphane haritası: hangi iş için hangi paket?

Veri, görselleştirme, makine öğrenmesi, web, kazıma, ofis otomasyonu, CLI, test, veritabanı ve doğrulama için doğru kütüphaneyi seçmeyi; PyPI'da paket değerlendirmeyi, belge okumayı (help, __doc__, inspect.signature), sürüm uyumunu ve typosquatting gibi güvenlik risklerini öğrenirsin.

Uygulamada aç, 19 alıştırmayı çözÜcretsiz, hesap gerekmez, kurulum yok.

Bu sayfa dersin okuma sürümüdür. Metin bir kutuyu çalıştırmanı ya da adıma geçmeni söylüyorsa dersi uygulamada aç.

Neden önemli?

Python'ın gücünün yarısı dilin kendisi, diğer yarısı da PyPI'daki (Python Package Index) yarım milyonu aşkın pakettir. Anadolu Market'te yeni başlayan bir analiste "aylık satış Excel'ini oku, grafiğini çiz, PDF raporunu e-postayla gönder" denildiğinde işin çoğu doğru kütüphaneyi seçmektir: Excel için openpyxl, analiz için pandas, grafik için matplotlib. Yanlış seçim haftalar kaybettirir; bakımı bırakılmış ya da sahte bir paket ise güvenlik açığı demektir.

Bu ders bir harita sunar: her iş alanında sektörde yaygın kabul gören kütüphaneler, kurulum komutları, bu uygulamada tarayıcıda çalışıp çalışmadıkları ve hangi derste derinleştirileceği. Ardından paketi nasıl değerlendireceğini, belgesini nasıl okuyacağını ve güvenlik tuzaklarını öğreneceksin. Sanal ortam (virtual environment) ve pip ayrıntılarını Sanal ortam ve paket yönetimi dersinde, standart kütüphaneyi Standart kütüphane turu dersinde gördün; burada bakış açısı "dışarıdan ne alırım?" sorusudur.

Komutu kopyalamadan önce adı resmî belgeden doğrula, requirements dosyalarını kod incelemesinden (code review) geçir, kurumda iç PyPI aynası kullan.

Bir de pip adı ile import adı farklı olabilir: pip install scikit-learn ama import sklearn; beautifulsoup4 → bs4; python-dateutil → dateutil; pyyaml → yaml; pillow → PIL. Bu farkı bilmeyenler "kurdum ama import edemiyorum" diye saatlerini harcar.

Belge okumak: help, __doc__, inspect

Yeni bir kütüphaneyi öğrenmenin sırası: resmî belgenin "Quickstart" bölümü, sonra API referansı. Kod içinden ise dört araç vardır:

import inspect, statistics

def kdv_hesapla(tutar: float, oran: float = 0.20, *, yuvarla: bool = True) -> float:
    """Tutara KDV ekler.

    oran ondalık verilir (0.20 = yüzde 20).
    """
    sonuc = tutar * (1 + oran)
    return round(sonuc, 2) if yuvarla else sonuc

imza = inspect.signature(kdv_hesapla)
print(imza)
for ad, p in imza.parameters.items():
    varsayilan = "zorunlu" if p.default is inspect.Parameter.empty else p.default
    print(f"  {ad:8} tür={p.kind.name:22} varsayılan={varsayilan}")
print(inspect.getdoc(kdv_hesapla).splitlines()[0])
print(inspect.signature(statistics.median))
print(statistics.median.__doc__.strip().splitlines()[0])

help(nesne) tüm bunları biçimlendirilmiş bir sayfa olarak yazdırır; etkileşimli kabukta en hızlı keşif aracıdır. dir(modul) içindeki adları, inspect.getdoc girintisi temizlenmiş belgeyi, inspect.signature parametreleri türleriyle birlikte verir. Parametre türleri PCAP ve gerçek API okuması için önemlidir: * sonrası parametreler yalnızca adla verilebilir (KEYWORD_ONLY).

Kurulu mu, hangi sürüm?

Bir paketi import etmek kodunu çalıştırır; yalnızca var olup olmadığını öğrenmek için importlib.util.find_spec kullan. Kurulu sürüm için importlib.metadata.version vardır.

import importlib.util
from importlib.metadata import version, PackageNotFoundError

for ad in ["json", "sqlite3", "olmayan_paket_xyz"]:
    print(ad, "kurulu" if importlib.util.find_spec(ad) else "YOK")

try:
    print("pip sürümü:", version("pip"))
except PackageNotFoundError:
    print("pip bu ortamda paket olarak kayıtlı değil")

# Sürüm karşılaştırma: metin değil, sayı demeti
a, b = "2.10.0", "2.9.3"
print(a > b)                                                    # yanlış sonuç!
print(tuple(map(int, a.split("."))) > tuple(map(int, b.split("."))))

Gerçek projede sürüm karşılaştırması için packaging.version.Version kullanılır; "2.0.0rc1" gibi ön sürüm etiketlerini de doğru sıralar. Semver (anlamsal sürümleme) kuralı: BÜYÜK.küçük.yama; büyük artış kırıcı değişiklik, küçük artış geriye uyumlu yeni özellik, yama artışı hata düzeltmesidir.

requirements dosyasından rapor

Yeni bir projeye katıldığında ilk iş requirements.txt ya da pyproject.toml dosyasını okumaktır; projenin ne yaptığını büyük ölçüde oradan anlarsın:

import re
from collections import defaultdict

requirements = """
pandas>=2.2       # analiz
openpyxl==3.1.2
fastapi[standard]>=0.110
pydantic~=2.7
pytest ; extra == 'test'
"""
KATALOG = {"pandas": "veri", "openpyxl": "ofis", "fastapi": "web", "pydantic": "doğrulama", "pytest": "test"}

rapor = defaultdict(list)
for satir in requirements.splitlines():
    satir = satir.split("#")[0].strip()
    if not satir:
        continue
    ad = re.split(r"[\[<>=!~; ]", satir, maxsplit=1)[0].lower()
    rapor[KATALOG.get(ad, "diğer")].append(ad)
for kategori, paketler in sorted(rapor.items()):
    print(f"{kategori:10} {', '.join(paketler)}")
Gerçek işteKurumsal ekiplerde yeni bir paket eklemek genelde bir onay sürecinden geçer: lisans kontrolü (hukuk), güvenlik taraması (pip-audit, Dependabot), bakım durumu ve "standart kütüphane ya da zaten kullandığımız bir paket bu işi yapıyor mu?" sorusu. Pull request açıklamasına "neden bu paket, alternatifleri neydi" yazmak iyi bir alışkanlıktır. Excel raporu, PDF birleştirme ve zamanlanmış görev gibi otomasyon işleri Python'a geçişin en sık nedenidir; bu işlerde openpyxl, pypdf ve APScheduler üçlüsü çok yaygındır.
Uzmanlaş

Bağımlılık ağacı ve çakışma

Bir paket kurmak onun bağımlılıklarını da kurar. pip install pandas numpy, python-dateutil, pytz ve tzdata'yı da getirir. İki paket aynı bağımlılığın uyumsuz sürümlerini isterse çakışma (dependency conflict) çıkar. pip check çakışmaları raporlar, pipdeptree ağacı gösterir. Az bağımlılıklı paketi tercih etmek uzun vadede kazandırır.

Wheel, saf Python ve derlenmiş paketler

numpy ve pandas gibi paketler C/Rust ile derlenmiş kod içerir; PyPI bunları işletim sistemi ve Python sürümüne özel wheel (.whl) dosyaları olarak sunar. Yeni bir Python sürümü çıktığında wheel henüz yoksa pip kaynaktan derlemeye çalışır ve derleyici hatası alırsın. Bu yüzden kurumlar yeni Python sürümüne birkaç ay gecikmeyle geçer. Tarayıcıdaki Pyodide da paketlerin WebAssembly'ye derlenmiş hâllerini kullanır; tablodaki "Hayır" satırlarının çoğu bu yüzdendir.

Belgeyi koddan üretmek

Kütüphanelerin API referans sayfaları çoğunlukla docstring'lerden otomatik üretilir (Sphinx, MkDocs + mkdocstrings). Kendi kodunda iyi docstring yazarsan aynı araçlarla belge siteni bedavaya alırsın ve help() senin kodunda da işe yarar.
