Sanal ortam ve paket yönetimi

venv ile projeye özel ortam kurar, pip ile paket yükler, requirements.txt ve pyproject.toml ile bağımlılıkları sürüm sabitleyerek yönetir, çatışmaları tanır ve uv/poetry gibi modern araçları tanırsın.

Uygulamada aç, 21 alıştırmayı çözÜcretsiz, hesap gerekmez, kurulum yok.

Sorun: "Benim makinemde çalışıyordu"

Anadolu Market'in raporlama betiği senin bilgisayarında kusursuz çalışıyor; iş arkadaşın çalıştırınca ModuleNotFoundError: No module named 'openpyxl' alıyor. Bir başka projede pandas'ın eski sürümü gerekiyor, ama bilgisayarına yenisini kurdun ve eski proje bozuldu. İki sorunun da kaynağı aynı: paketler (package) bilgisayara global kurulmuş. Çözüm iki parçalı: her projeye kendi izole paket klasörü (sanal ortam, virtual environment) ve projenin hangi paketlerin hangi sürümünü istediğini yazan bir liste (requirements.txt ya da pyproject.toml).

Bu derste terminal komutları gösterilirTarayıcıdaki Python'da pip ya da venv çalıştıramayız; komutları kendi bilgisayarında dene. Kod alıştırmaları ise bu araçların ürettiği metin dosyalarını Python ile ayrıştırmak üzerine; iş hayatında da tam bunu yaparsın: CI betiği requirements'ı okur, sürümü kontrol eder.

Sanal ortam: venv

venv, standart kütüphanenin parçasıdır. Proje klasöründe şu üç komut yeter:

  1. python -m venv .venv — proje içinde .venv klasörü oluşturur; içinde ayrı bir Python ve boş bir paket klasörü vardır.
  2. Etkinleştir: Windows'ta .venv\Scripts\activate, macOS/Linux'ta source .venv/bin/activate. Terminal satırının başında (.venv) belirir.
  3. Artık pip install yalnızca bu klasöre kurar; deactivate ile çıkarsın.

Kural: her proje kendi .venv'ine sahip olur ve bu klasör asla Git'e girmez (sonraki derste .gitignore'a yazacağız). Ortamı başkasıyla paylaşmazsın; paylaştığın şey bağımlılık listesidir, ortamı herkes kendi makinesinde o listeden yeniden kurar.

import sys
from pathlib import Path

# Sanal ortam etkin mi? sys.prefix sanal ortamın yolunu, base_prefix gerçek kurulumu gösterir
etkin = sys.prefix != sys.base_prefix
print("sanal ortam etkin mi?", etkin)
print("Python sürümü:", sys.version_info.major, ".", sys.version_info.minor, sep="")

# Tipik bir proje yerleşimi (gösterim)
agac = {
    "anadolu-rapor/": ["pyproject.toml", "requirements.txt", "README.md", ".gitignore", ".venv/  (Git'e girmez)", "src/anadolu_rapor/", "tests/"],
}
for kok, parcalar in agac.items():
    print(kok)
    for p in parcalar:
        print("  ", p)

Sürüm belirteçleri ve semver

Paketler çoğunlukla anlamsal sürümleme (semantic versioning, semver) kullanır: MAJOR.MINOR.PATCH. PATCH hata düzeltmesidir, MINOR geriye uyumlu yeni özellik, MAJOR ise uyumu bozabilen değişiklik. requirements.txt satırında hangi sürümleri kabul ettiğini belirtirsin:

BelirteçAnlamıNe zaman
pandas==2.2.2Tam olarak 2.2.2Dağıtım, tekrarlanabilirlik
pandas>=2.02.0 ve üstü, sınırsızKütüphane yazarken (esnek)
pandas~=2.2.0>=2.2.0 ve <2.3 (son basamak serbest)Yama güncellemelerine açık
pandas>=2.0,<32.x serisiMAJOR kırılmasından korunmak
pandasHerhangi bir sürümHızlı deneme; üretimde kaçın

Sürüm metnini karşılaştırırken metin karşılaştırması yanıltır: "2.10.0" < "2.9.0" metin olarak doğru ama sürüm olarak yanlıştır. Parçalara bölüp tam sayıya çevirmek gerekir; aşağıdaki küçük ayrıştırıcı requirements satırlarını sözlüğe döker ve sürümü doğru karşılaştırır.

import re

def surum_demeti(s: str) -> tuple[int, ...]:
    return tuple(int(p) for p in s.split("."))

print('"2.10.0" < "2.9.0" metin olarak:', "2.10.0" < "2.9.0")
print("demet olarak:", surum_demeti("2.10.0") < surum_demeti("2.9.0"))

requirements = """
# Anadolu Market rapor aracı
pandas==2.2.2
openpyxl>=3.1
requests~=2.31.0

rich
"""
desen = re.compile(r"^([A-Za-z0-9_.-]+)\s*(==|>=|~=|<=|>|<)?\s*([0-9.]+)?$")
for satir in requirements.splitlines():
    satir = satir.strip()
    if not satir or satir.startswith("#"):
        continue
    ad, op, ver = desen.match(satir).groups()
    print(f"{ad:10} {op or '(her sürüm)':12} {ver or ''}")

Düzenli ifade üç parça yakalar: paket adı, işleç, sürüm. Yorum ve boş satırlar atlanır. Gerçek requirements dosyalarında ek kurallar da bulunur (ortam işaretleri, -r ile başka dosya), ama günlük işte bu kadarı yeter.

~= tuzağı~=2.2 ile ~=2.2.0 farklıdır. İlki ">=2.2, <3.0" (minor serbest), ikincisi ">=2.2.0, <2.3" (yalnızca patch serbest). Son basamak kaç haneli yazıldıysa o basamak serbest kalır.

pyproject.toml: modern standart

Yeni projelerde bağımlılıklar requirements.txt yerine (ya da onunla birlikte) pyproject.toml içinde tutulur. TOML, okunur bir yapılandırma biçimidir; Python 3.11'den beri standart kütüphanedeki tomllib ile okunur (yalnızca okuma; yazmak için dış paket gerekir). Aynı dosya projenin adını, sürümünü ve araç ayarlarını da taşır.

import tomllib

pyproject = """
[project]
name = "anadolu-rapor"
version = "0.3.1"
requires-python = ">=3.11"
dependencies = [
    "pandas==2.2.2",
    "openpyxl>=3.1",
]

[project.optional-dependencies]
dev = ["pytest>=8", "ruff"]

[tool.ruff]
line-length = 100
"""
veri = tomllib.loads(pyproject)
proje = veri["project"]
print(proje["name"], proje["version"], "| Python:", proje["requires-python"])
print("bağımlılıklar:", proje["dependencies"])
print("geliştirme:", proje["optional-dependencies"]["dev"])
print("ruff satır uzunluğu:", veri["tool"]["ruff"]["line-length"])

optional-dependencies altındaki dev grubu yalnızca geliştiricilerin kurduğu paketlerdir (test, biçimlendirici); pip install -e ".[dev]" ile kurulur. Üretim sunucusuna pytest kurmazsın.

uv ve poetrypip + venv her yerde çalışır ama yavaş ve elle yönetimlidir. uv (Rust ile yazılmış, çok hızlı) ve poetry, sanal ortamı ve kilit dosyasını (lock file) otomatik yönetir: uv add pandas hem pyproject'e yazar hem kurar hem uv.lock üretir. Kilit dosyası, pip freeze'in modern karşılığıdır: her bağımlılığın bağımlılığının bile tam sürümünü tutar.

Bağımlılık çatışması

Paket A, requests>=2.31 isterken paket B requests<2.30 isterse pip "ResolutionImpossible" hatası verir: iki koşulu aynı anda sağlayan sürüm yok. Çatışma (dependency conflict) genellikle eski bir paketin güncellenmemesinden doğar. Çözüm sırası: önce iki paketin daha yeni sürümlerini dene; olmuyorsa birini değiştir; son çare, çatışan işi ayrı sanal ortamda çalışan ayrı bir araca taşı. Çatışmayı erken fark etmek için bağımlılık listesini küçük tut: gerçekten kullandığın paketleri yaz, "bir gün lazım olur" diye ekleme.

def aralikta(ver: tuple, kosullar: list[tuple[str, tuple]]) -> bool:
    for op, hedef in kosullar:
        if op == ">=" and not ver >= hedef: return False
        if op == "<" and not ver < hedef: return False
        if op == "==" and not ver == hedef: return False
    return True

# A: requests>=2.31  |  B: requests<2.30
kosullar = [(">=", (2, 31, 0)), ("<", (2, 30, 0))]
adaylar = [(2, 28, 0), (2, 29, 0), (2, 31, 0), (2, 32, 3)]
uygun = [v for v in adaylar if aralikta(v, kosullar)]
print("iki koşulu da sağlayan sürüm:", uygun or "YOK -> çatışma")

3. requirements ve constraints

requirements.txt "bunları kur" der. constraints.txt (-c) ise "kurarsan şu sürümü kullan" der ama kendisi hiçbir şey kurmaz. Şirket genelinde onaylı sürümleri tek dosyada tutmak için idealdir: her proje kendi requirements'ını yazar, sürümler ortak constraints'ten gelir.

# requirements.txt
pandas>=2.2
requests
-c constraints.txt        # dosya içinden de bağlanabilir

# constraints.txt  (şirket onaylı sürümler)
pandas==2.2.3
numpy==2.1.3
requests==2.32.3
django==5.1.4             # kimse istemezse kurulmaz

python -m pip install -r requirements.txt -c constraints.txt

Kurulu sürümleri Python içinden okumak (ör. bir betiğin başında "doğru sürüm mü?" kontrolü) için importlib.metadata kullanılır:

from importlib.metadata import version, PackageNotFoundError

for paket in ("pip", "pandas", "olmayan-paket-xyz"):
    try:
        print(f"{paket:20} {version(paket)}")
    except PackageNotFoundError:
        print(f"{paket:20} KURULU DEĞİL -> python -m pip install {paket}")

9. Sık hatalar: PEP 668, SSL, proxy, sürüm çakışması

PEP 668 – error: externally-managed-environment. Ubuntu 23.04+, Debian 12+, Fedora ve Homebrew Python'ı sistem paket yöneticisine aittir; pip ile global kurulum engellenir. Çözüm her zaman bir sanal ortam (proje için) ya da pipx (araç için) kullanmaktır. --break-system-packages bayrağı adının söylediğini yapar: işletim sistemi araçlarını bozabilir.

SSL – CERTIFICATE_VERIFY_FAILED. Kurumsal ağlarda güvenlik cihazı trafiği kendi sertifikasıyla yeniden imzalar. Doğru çözüm şirketin kök sertifikasını tanıtmaktır; doğrulamayı kapatmak değil.

python -m pip install --upgrade pip              # pip 24.2+ sistem sertifika deposunu (truststore) kullanır
python -m pip config set global.cert C:\sertifikalar\sirket-kok.pem
# ya da ortam değişkeniyle (PowerShell: $env:PIP_CERT = "...")
export PIP_CERT=/etc/ssl/certs/sirket-kok.pem
export REQUESTS_CA_BUNDLE=/etc/ssl/certs/sirket-kok.pem   # requests/httpx için
# macOS python.org kurulumunda: "Install Certificates.command" dosyasını çalıştır

# Proxy: 407 Proxy Authentication Required / ProxyError
export HTTPS_PROXY=http://kullanici:parola@proxy.sirket.local:8080
python -m pip install --proxy http://proxy.sirket.local:8080 pandas
# Şirket içi ayna (Artifactory/Nexus)
python -m pip config set global.index-url https://nexus.sirket.local/repository/pypi/simple

from collections import defaultdict

hata = """ERROR: Cannot install anadolu-rapor and eski-grafik because these package versions have conflicting dependencies.
